# 0012: 受信データの上限と、応答に載せるエラー文の範囲を決める

- ステータス: 採用
- 日付: 2026-10-05

## 背景

GitHub issue #7 で、サーバーの入力検証とエラーの扱いに次の弱点が見つかった。

- `POST /api/ingest` の数値は `0` 以上であることしか検証しておらず、`1e308` や小数の歩数、起床が就寝より前の睡眠も保存できた
- ノート同期の結果（`failed[].error`）や、同期が例外を投げたときの応答に、内部のエラー文（通信先のアドレスや MCP サーバーの応答など）をそのまま載せていた
- CouchDB へのリクエストにタイムアウトが無く、応答の無い CouchDB で処理が止まり続けた
- Takeout の極端な時刻で `toISOString` が `RangeError` を投げ、取り込み全体が止まった
- DB から読んだ `date` を再検証せず、ノートのパスや YAML に使っていた

## 決定

- 各項目に上限を設ける。上限は実在のデータを弾かないよう、人が取りうる値より十分大きくする（誤送信や桁違いを止めるのが目的）。歩数だけは整数に限る。Android と Takeout はどちらも整数を送るが、Takeout の取り込みでは念のため丸める。分・kcal・g などは Takeout が小数を出すので小数を許す

  | 項目 | 上限 |
  |---|---|
  | `steps` | 200,000（整数） |
  | `distance_m` | 500,000 |
  | `calories_kcal` / `energy_kcal` | 50,000 |
  | `move_minutes` / `vigorous_minutes` / `walking_minutes` | 1,440 |
  | `heart_points` | 5,000 |
  | 心拍（`*_bpm`） | 300 |
  | `weight_kg` | 500 |
  | `body_fat_pct` | 100 |
  | `protein_g` / `fat_g` / `carbs_g` | 5,000 |
  | 睡眠の分（`*_minutes`） | 2,880（前日から続くため 1 日を超えうる） |

- 睡眠の `start` と `end` が両方あれば、`start <= end` を求める（片方だけ、または `null` は従来どおり受け付ける。省略は既存の値を残し、`null` は消す）
- 応答に載せるエラー文は、利用者が対処できる既知のエラーだけにする。メモ欄のマーカー欠落（`MemoMarkerMissingError`）と Vault パスの違反（`VaultPathError`。`VAULT_HEALTH_PREFIX` の設定の見直しで直る）は文面をそのまま返し、それ以外は「Vault への書き込みに失敗しました。詳細はサーバーのログを確認してください」などの固定の文にする。詳細は `console.error` でログに残す。ログには `cause` をたどらず、エラーの名前と（トークンを伏せた）文面だけを出す
- CouchDB へのリクエストは既定 10 秒で打ち切る
- Takeout の時刻は 2000〜2100 年の範囲だけを受け付け、範囲外の記録は捨てて件数を表示する
- DB から読んだ日付が実在する `YYYY-MM-DD` でなければ、その日のノートは作らず `failed` に載せる。前後の日を求めるときも読み飛ばす

## 検討した選択肢

| 選択肢 | 長所 | 短所 |
|---|---|---|
| **既知のエラーだけ文面を返し、他は固定の文にする** | 対処できる失敗は利用者に伝わる。内部の情報が外に出ない | 原因を調べるにはサーバーのログを見る必要がある |
| すべてのエラー文をそのまま返す（従来） | 原因がすぐ分かる | 通信先や MCP サーバーの応答など、内部の情報が応答に出る |
| すべて固定の文にする | 最も漏れにくい | マーカー欠落のように利用者が直せる失敗も、ログを見ないと分からない |
| 上限を厳しく（実際の最大値に近く）する | 誤ったデータをより多く止められる | 実在のデータ（長時間の運動や睡眠など）を弾くおそれがある |

## 結果

- 桁違いの値や前後が逆の睡眠は 400 で拒否される。上限を超える実在のデータが出てきたら、新しい ADR で上限を見直す
- `sync:notes` などのクライアントは、固定の文が返ったらサーバーのログを確認する
- 既に DB にある値は再検証しない（日付を除く）。上限を超える古い値があっても、ノートの生成はそのまま行う
