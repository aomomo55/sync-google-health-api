# 0009: 日次ノートのメモ欄を消さないよう、不在の判定とマーカーの無いノートの扱いを厳しくする

- ステータス: 採用
- 日付: 2026-10-05

## 背景

[0007](0007-write-via-obsidian-sync-mcp.md) のとおり、obsidian-sync-mcp の `write_note` はノート全体を置き換える。そのため日次ノートは `read_note` で読み、`%% health:memo` の行より下（利用者のメモ欄）を残して書き込んでいる。

この処理には、メモ欄が消えうる経路が 2 つあった（GitHub issue #2）。

- `read_note` の応答に `not found` や `does not exist` が**どこかに含まれていれば**、エラーかどうかを確かめる前に「ノートは無い」とみなしていた。チャンクの欠損やデータベースの異常などのエラー文でも不在と判定され、既存のノートを新規の内容で上書きしてしまう
- 既存のノートにメモ欄のマーカーが無いとき、`mergeMemo` は生成した内容をそのまま返していた。利用者がマーカーの行を消した、または同じパスに手書きのノートがあると、本文がすべて失われる

## 決定

- `read_note` で「ノートが無い」とみなすのは、本文が obsidian-sync-mcp の不在の応答 `Note not found: <要求したパス>` と**完全に一致する**ときだけにする（obsidian-sync-mcp はこの応答に `isError` を付けないので、`isError` の有無は判定に使わない）。それ以外のエラーは失敗として扱い、そのノートは書き込まない。実在するノートは必ず `[Open in Obsidian]` の前置き付きで返るので、本文と取り違えることはない
- 空でない既存の日次ノートにマーカーの行が無ければ、上書きしない。同期の結果では `failed` に載せ、「マーカーが無いため上書きしなかった。マーカーの行を戻すか、ノートを削除すると再生成される」旨を日本語で示す。空白だけのノートは空とみなして上書きする
- 他のノートの同期は続ける（1 件の失敗で全体を止めない）

## 検討した選択肢

| 選択肢 | 長所 | 短所 |
|---|---|---|
| **マーカーの無いノートは上書きせず失敗として報告する** | 利用者の文章を失わない。原因と対処が結果に出る | 利用者が直すまで、その日のノートは更新されない |
| マーカーの無いノートは生成した内容で置き換える（従来） | 常に最新の内容になる | 手書きの文章やマーカーを消したノートが黙って失われる |
| 既存の本文をメモ欄の下に退避して書き込む | 更新は止まらない | 同期のたびに退避が重なりうる。ノートの構造が予想しにくくなる |

## 結果

- 不在以外のエラーやマーカーの無いノートで、利用者のメモが上書きされなくなる
- 同期の結果（`POST /api/ingest` の `notes.failed`、`POST /api/notes/sync` の `failed`、`sync:notes` の終了コード）に、上書きしなかったノートが失敗として現れる。利用者がマーカーを戻すかノートを削除すれば、次の同期で更新される
- obsidian-sync-mcp が不在の文言を変えると、存在しないノートの読み出しが失敗扱いになり、新しい日次ノートを作れなくなる。その場合は判定の文言を合わせる
- **既知の制限**: 0007 の事例のように、obsidian-sync-mcp 自身が既存のノートに対して誤って「Note not found」を返す場合は、応答から見分けられない。これは引き続き 0007 の LiveSync の設定（パスフレーズ由来の ID キー、難読化オフ）を守ることで防ぐ
