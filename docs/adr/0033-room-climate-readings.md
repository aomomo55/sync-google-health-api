# 0033: 寝室の温湿度を GAS から受け取り、夜の値を日次ノートに書く

- ステータス: 採用
- 日付: 2026-11-15

## 背景

寝室の温湿度と睡眠の関係を見たい。温湿度計（SwitchBot）は 30 分おきの記録を持っているが、アプリから CSV を手で書き出すしかなく、睡眠のデータと突き合わせるには毎回手作業が要る。

- SwitchBot の API で取れるのは今の値だけで、過去の記録は取れない。続けて記録するには、誰かが 30 分おきに読みに行く必要がある
- サーバー（fly.io）は自動停止するので、サーバーの中のタイマーでは定期実行できない。定期実行は GAS の時間主導トリガーに寄せている（バックアップと同じ）
- 夜の温湿度は「就寝〜起床の間」で見たい。睡眠のデータは起床後に Android から届くので、温湿度は届いた時点では夜に割り当てられない

## 決定

- **GAS（`gas/room-climate.gs`）が 30 分おきに SwitchBot API で今の値を読み、サーバーの `POST /room/readings` に送る**。送れなかった値は GAS のスクリプト プロパティに残し（2 日分まで）、次の実行で一緒に送る
- `/room/*` は専用のトークン `ROOM_TOKEN` で守る。`API_TOKEN`・`BACKUP_TOKEN` とは別の値にし、互いの経路を使えないようにする。漏れても温湿度を書き込めるだけで、健康データは読み書きできない。設定が無ければ経路を作らない
- サーバーは読み取り値（時刻・温度・湿度）を、Asia/Tokyo の日付ごとの CouchDB の文書（`room:YYYY-MM-DD`）に保存する。同じ分の値は置き換える。受け取ってもノートは作らない
- 日次ノートを作るときに、その日の睡眠の就寝〜起床の間にある読み取り値から、平均・最低・最高の室温と平均の湿度を求め、プロパティ `夜平均室温`・`夜最低室温`・`夜最高室温`・`夜平均湿度` に書く。Android の送信（1 時間おき・直近 7 日）のたびに日次ノートは作り直されるので、睡眠のデータが届いた後の送信で値が入る
  - 就寝〜起床の間に、1 時間あたり平均 1 件以上の読み取り値が無い夜は空にする（送信が何時間も止まった夜を、残った数件で代表させないため）
  - 温湿度を読めなかったとき（CouchDB の一時的なエラー、文書の形の不正など）は、ログに残して温湿度を空にし、日次ノートの同期は続ける。補助の計測が壊れただけで、睡眠や歩数のノートが止まらないようにするため
  - 読むのは、作り直す日次ノート（対象の日と前後の日）の夜の分だけにする。月次の集計のために読む月全体の分は読まない
  - 温湿度計は後から足した計測なので、本文の「寝室（睡眠中）」の行は値のある日だけ出す（睡眠・食事のように「記録なし」とは書かない。[0028](0028-show-missing-sleep-and-nutrition-in-notes.md) の対象外）
- サーバーと保存の形はメーカーを知らない。SwitchBot の形式を知っているのは、GAS と、過去の CSV を送る CLI（`import:room-csv`）だけにする
- 睡眠ダッシュボードに、直近 30 夜の夜の室温・湿度のグラフを足す。あわせて、利用者が書いた分析のノート（`type: health-analysis`）を一覧にする欄を足す。ダッシュボードは自動生成なので、個々のノートへのリンクは書かない
- 温湿度はバックアップ（`GET /backup/health`）に含めない。失っても温湿度計のアプリに記録が残っていれば、CSV から入れ直せる

## 検討した選択肢

| 選択肢 | 長所 | 短所 |
|---|---|---|
| **A: GAS が SwitchBot API を読み、サーバーへ送る** | 定期実行の置き場所がほかと同じ（GAS）。SwitchBot のトークンをサーバーに置かない。サーバーは受け取るだけ | GAS のプロジェクトが 1 つ増える。GAS のコードはリポジトリから自動で配置されない |
| B: サーバーが SwitchBot API を読み、GAS は起こすだけ | SwitchBot の形式をサーバーに閉じ込められる | SwitchBot のトークンをサーバーの secrets に置くことになる。メーカーの形式がサーバーに入る |
| C: GAS がスプレッドシートに貯めるだけ | サーバーを変えなくてよい | 日次ノートやダッシュボードに出ない。分析のたびに突き合わせが要る |
| D: 夜の値を GAS で決まった時間帯（0〜6 時など）で集計して送る | サーバーで夜を割り当てなくてよい | 就寝・起床の時刻と合わない。GAS が睡眠のデータを知らない |

経路を `/api/*` に入れて `API_TOKEN` を使う案は採らなかった。GAS に書き込み用のトークンを置くことになり、漏れたときの被害が大きい（バックアップと同じ考え方）。

## 結果

- 寝室の温湿度が、睡眠と同じ日次ノートに並ぶ。Bases やダッシュボードで睡眠の値と並べて見られる
- 過去の分は `import:room-csv` で送り、`sync:notes` で日次ノートを作り直すと入る
- GAS を変えたら、利用者が GAS のエディタに貼り直す必要がある。SwitchBot API の 1 日の上限は 10,000 回で、30 分おきなら 48 回
- 日次ノートのプロパティが 4 つ増える。作り直していない古いノートにはキーが無い
- 温湿度計を替えるときは、GAS と CSV の読み込みだけを替えればよい
