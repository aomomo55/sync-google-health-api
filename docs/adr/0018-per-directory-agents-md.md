# 0018: エージェント向けの指示をディレクトリごとの AGENTS.md に分ける

- ステータス: 採用
- 日付: 2026-10-07

## 背景

ルートの AGENTS.md が 100 行を超えた。中身には、リポジトリ全体の約束のほかに、サーバーだけに関わるもの（層と依存の向き、pnpm のコマンド、ノートの生成の前提）、Android だけに関わるもの（JDK 21）、デプロイの手順が混ざっていた。

ディレクトリごとに言語も扱う分野も違う（TypeScript のサーバー / Kotlin の Android / GAS）。今後、ディレクトリを単位にしてサブエージェントに作業を任せることも考えられる。その場合、そのディレクトリに関係する指示だけがまとまっていると渡しやすい。

## 決定

- ルートの AGENTS.md には、リポジトリ全体に共通する約束、サーバーと Android にまたがる前提、セキュリティ、秘密情報の扱いを書く
- `server/`・`android/`・`gas/` にそれぞれ AGENTS.md を置き、そのディレクトリの構成・コマンド・前提を書く
- ルートの AGENTS.md に、作業するディレクトリの AGENTS.md も必ず読むことを書く
- デプロイの手順は、エージェント向けの指示ではなく利用者向けの手順書として `docs/deploy.md` に移す。AGENTS.md には、案内するときの書き方の約束だけを残す
- ルールを変えたら、AGENTS.md（ルートとディレクトリごと）と REVIEW.md の両方を見直す

## 検討した選択肢

| 選択肢 | 長所 | 短所 |
|---|---|---|
| ディレクトリごとの AGENTS.md（採用） | 作業する場所の近くに指示がある。ディレクトリ単位のサブエージェントにそのまま渡せる。多くのツールがディレクトリの AGENTS.md を読む | ファイルが増え、どこに書くかを判断する必要がある。全体の約束と食い違うおそれがある |
| `docs/rules/` に分ける | 1 か所にまとまる | 自動では読まれず、リンクをたどったときにしか読まれない。必ず守ってほしいルールが読み飛ばされやすい |
| ルートの AGENTS.md 1 つのまま | 迷わない | 長くなり、関係の無いルールまで毎回読むことになる |

## 結果

- サーバーだけ、Android だけの作業では、ルートとそのディレクトリの AGENTS.md を読めば足りる
- 全体の約束とディレクトリの指示が食い違わないよう、ルールの変更時に両方を見直す必要がある。REVIEW.md に、新しいトップレベルのディレクトリには AGENTS.md を作るという確認項目を加えた
