# 0030: ノートの書き込みの失敗も送信の失敗に数え、続いたら同じ仕組みで通知する

- ステータス: 採用
- 日付: 2026-10-25

## 背景

`POST /api/ingest` は、健康データを保存した後でノートを書き込む。ノートの書き込みに失敗しても、保存は済んでいるので 200 を返し、応答の `notes.failed`（書き込めなかったノートごとの `path` と `error` の配列）か `notes.error`（同期そのものの失敗）で知らせる。`notes.failed` の `error` には、obsidian-sync-mcp との通信の失敗のような送り直せば直るもの（一般的な失敗の文）のほか、日次ノートのメモ欄のマーカーが無い、パスが不正、保存されている日付が不正、のように送り直しでは直らないものも入る。どの理由の文にも、次にすることが書いてある。

[0026](0026-notify-sync-failures.md) では、送信の結果が成功（`SyncStatus.OK`）なら失敗の連続回数を消し、失敗の通知も消していた。そのため obsidian-sync-mcp が止まってノートを書き込めない状態が続いても、Android アプリは成功として扱い、通知は出なかった。画面では、結果の文の途中に件数が混ざるだけだった（Issue #91 で「注意:」の行に出すようにした）。

利用者が毎日見るのはアプリの画面より通知とノートなので（[docs/review/ux.md](../review/ux.md)）、ノートが更新されないまま古いノートで朝の判断をしてしまうおそれがある。

## 決定

- ノートの書き込みに失敗した送信（`notes.failed > 0` または `notes.error` がある）も、失敗の連続回数（`FailureStreak`）に数える。送信の結果（`SyncStatus`）は `OK` のままにし、連続回数と通知の判定でだけ失敗として扱う（`attemptSucceeded`）
- 通知の条件は 0026 のまま変えない（2 回以上続き、3 時間以上続いた。睡眠を確かめる時間帯の中は時間を待たない。1 日 1 回まで、音は鳴らさない、手動の送信では通知しない）。送信の失敗とノートの失敗は同じ連続回数に数え、同じ通知（同じチャンネル・同じ ID）を使う
- Android は `notes.failed` の各要素の `path` と `error` を取り込む（形が不正な要素も件数には数え、理由は「不明」として出す）。画面の「注意:」の行と通知の原因には、理由ごとに 1 行で、書き込めなかったノートのファイル名（パスの最後の部分）とサーバーの理由の文を出す。理由が多いときは 3 つまでにし、残りは件数だけにまとめる
- 次にすること（obsidian-sync-mcp を確かめる、メモ欄のマーカーを戻す、など）は、アプリでは足さず、サーバーの理由の文に任せる。アプリがサーバーの文言を見て案内を選ぶと、サーバーの文を変えたときに食い違って誤った案内になるため。理由が返らなかったときだけ、アプリの文で obsidian-sync-mcp を確かめるよう添える
- 通知の文は、ノートだけの失敗のとき次のようにする
  - タイトルを「ノートを書き込めていません」にする
  - 原因には上の「注意:」と同じ文を出す
  - 案内の行は「健康データは保存できていて、ノートだけを書き込めていません。次にすることは原因の文に書いてあります」とし、原因の文と同じ案内をくり返さない
  - 睡眠の未反映はデータが届いていれば判定できるので、「送れていない間は、睡眠の未反映の通知も出ません」は添えない
- 「最後に成功した時刻」は、ノートまで書き込めた時刻にする。ノートだけの失敗では更新しない。通知の「それより後のデータはノートに入っていません」と、画面の「最後に成功」が食い違わないようにするため
- 画面では、最後に試した送信がノートだけの失敗なら「（データは保存、ノートの書き込みに失敗）」と添え、結果の文は「エラー:」ではなく通常の「結果:」で出す（データは保存できているため）。ノートの失敗の内容は「注意:」の行に出す
- 睡眠の未反映の判定（[0027](0027-recheck-missing-sleep-in-window.md)）は、データを送れていれば、ノートの失敗にかかわらず行う
- 値が範囲外で保存されなかった日は、これまでどおり失敗には数えない（他の日は保存されていて、送り直しても直らないため。画面の「注意:」で知らせる）

## 検討した選択肢

| 選択肢 | 長所 | 短所 |
|---|---|---|
| アプリが理由の文言を見て、送り直せば直る失敗のときだけ obsidian-sync-mcp の案内を足す | 理由の文が短くても案内が出る | サーバーの文言に依存し、文を変えると誤った案内になる。サーバーの文にも同じ案内があり、くり返しになる |
| ノートの失敗を同じ連続回数に数え、同じ通知を使う（採用） | 条件・チャンネル・1 日 1 回の数え方を増やさずに済む。送信とノートの失敗が交互に起きても続いていることが分かる | 送信の失敗を通知した日は、後でノートの失敗に変わっても、その日はもう通知しない（内容が新しくならない） |
| ノートの失敗には別の連続回数・別の通知を使う | 種類ごとに止めたり内容を分けたりできる | 状態と通知が倍になる。両方が同時に出ると、朝に読む通知が増える |
| 送信の結果をノートの失敗のときも `FAILED` にする | 判定が 1 か所で済む | データは保存できているのに、画面で「エラー:」になり、ワーカーも失敗として終わる。睡眠の未反映の判定も止まる |
| 通知はせず、画面の「注意:」だけにする（Issue #91 の前半の状態） | 変更が小さい | アプリを開くまで気づけない |

## 結果

- obsidian-sync-mcp が止まるなどでノートを書き込めない状態が続くと、アプリを開かなくても通知で気づける
- この版に更新した後は、ノートだけが失敗した送信で「最後に成功」の時刻が進まない。ノートの失敗が 12 時間以上続くと、画面の「注意:」で成功していないことも示す
- メモ欄のマーカーを消した日次ノートのように、送り直しでは直らない失敗も通知に出る。通知には直し方が出るので、直すまで（1 日 1 回）知らせ続ける
- 失敗の通知は 1 日 1 回のままなので、同じ日に送信の失敗からノートの失敗へ変わった場合、通知の内容は最初の失敗のままになる
- 判定（`attemptSucceeded`・`nextFailureStreak`・`syncFailureAction`・`failureNotice`）は引き続き `SyncFailureCheck.kt` の純粋な関数で、テストを置く
