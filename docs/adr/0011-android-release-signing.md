# 0011: Android アプリのリリース署名は仕組みだけを用意し、鍵は利用者が管理する

- ステータス: 採用
- 日付: 2026-10-05

## 背景

[0008](0008-android-app-health-connect-mapping.md) では、デバッグ署名の APK を手動でインストールすることにした。
デバッグ署名の APK は debuggable で、鍵はビルドする PC ごとに自動で作られる。そのため次の問題がある。

- adb からアプリのデータを読んだりデバッガーをつないだりできる
- PC を替えると署名が変わり、上書きで更新できない

一方で、CI は `./gradlew testDebugUnitTest assembleDebug` を鍵なしで実行しており、鍵をリポジトリや CI に置くつもりはない。

## 決定

- `android/app/build.gradle.kts` に `release` の署名設定を加える。キーストアのパス・パスワード・鍵の別名・鍵のパスワードは、`android/keystore.properties`（git 管理外）か環境変数 `ANDROID_RELEASE_*` から読む（ファイルの値を優先）。
- 4 つの値が揃っているときだけ release ビルドに署名を設定する。揃っていなければ今までどおり署名しない（デバッグビルドと CI は影響を受けない）。一部だけあるときは警告を出す。
- release は debuggable にしない（既定のまま）。
- 鍵の作成・保管・バックアップは利用者が行い、手順を `android/README.md` に書く。鍵とパスワードはリポジトリに入れない（`.gitignore` に `android/keystore.properties`・`*.jks`・`*.keystore` を追加）。
- デバッグ署名の APK を使う運用は残す（0008 を置き換えるのではなく、選択肢を足す）。デバッグ版を使う間は USB デバッグをオフにすることを推奨する。

## 検討した選択肢

| 選択肢 | 長所 | 短所 |
|---|---|---|
| **仕組みだけ用意し、鍵は利用者が管理する** | 鍵が外に出ない。CI はそのまま | 鍵の紛失に備えたバックアップを利用者が引き受ける |
| CI の secrets に鍵を置いて署名済み APK を作る | ビルドする PC に依存しない | 鍵を第三者のサービスに預けることになる。利用者は一人で、配布の自動化は要らない |
| デバッグ署名のまま運用する | 手間がない | debuggable のまま。PC を替えると更新できない |

## 結果

- 利用者は自分の鍵でリリース版を作り、PC を替えても同じ鍵で上書き更新できる。
- デバッグ版からリリース版へ切り替えるときは署名が違うため一度アンインストールが必要で、API トークンの入力とヘルスコネクトの権限付与をやり直す。
- 鍵を失うと同じアプリとして更新できない。バックアップは利用者の責任になる。
