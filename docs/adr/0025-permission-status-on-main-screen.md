# 0025: 画面の権限の表示を、足りないものに合わせて出し分ける

- ステータス: 採用
- 日付: 2026-10-24

## 背景

アプリの画面では、ヘルスコネクトの権限が 1 つでも欠けると「未付与または不足」とだけ出し、どの権限が足りないかが分からなかった。「権限を付与」のボタンは、権限がそろっていても出したままだった。

通知の権限（`POST_NOTIFICATIONS`）は [0022](0022-notify-missing-sleep.md) で「権限を付与」の流れの中で求めることにしたが、次の点が残っていた。

- 未付与のときの文が補足用の小さい字で、足りないことに気づきにくい
- ヘルスコネクトの権限がそろっていると、通知の権限だけを求め直す手段が無い
- 2 回拒否すると OS が許可のダイアログを出さなくなるが、そのあとの手段（アプリの通知設定）が示されない

## 決定

- ヘルスコネクトの権限は、足りないものの名前（睡眠、心拍数など）を並べる。送信に必須のものと任意のもの（栄養・履歴）を分ける
- 「権限を付与」のボタンは、足りないものに合わせて出し分ける
  - 必須の権限が足りない: 塗りつぶしのボタン「権限を付与」
  - 任意の権限だけが足りない: 枠だけのボタンで、足りない権限の名前を添える
  - そろっている: ボタンを「ヘルスコネクトの権限を見直す」に替え、ヘルスコネクトの画面を開く（あとで権限を外したり確かめたりする手段を残すため）
- 通知の権限は、未付与のときにヘルスコネクトの権限と同じ見た目（「要対応:」の見出し語と error の色）で出し、通知の権限だけを求めるボタンを置く。「権限を付与」の流れの中で求めることは 0022 のまま続ける
- 通知の権限を一度でも求めたかを端末に保存し、`shouldShowRequestPermissionRationale` と合わせて「2 回拒否された」状態を見分ける。その状態では、ボタンをアプリの通知設定を開くものに替える
- 判定（足りない権限の名前、通知の権限の状態）は Android に依存しない純粋な関数（`PermissionStatus.kt`）にしてテストする
- 画面に戻ってきたとき（`ON_RESUME`）に権限を読み直し、設定アプリやヘルスコネクトで変えた結果を反映する

## 検討した選択肢

| 選択肢 | 長所 | 短所 |
|---|---|---|
| 足りないものに合わせて出し分け、そろったら「見直す」ボタンにする（採用） | 要る操作だけが目立つ。見直す手段も残る | 画面の状態の組み合わせが増える |
| そろったら権限のボタンを消す | 画面が一番すっきりする | 権限を確かめたり外したりする入口が、アプリの外（ヘルスコネクトの設定）にしか無くなる |
| ボタンは出したままにし、文だけ変える | 変更が小さい | 権限がそろっていても押せるので、要らない操作に見える |
| 「2 回拒否された」の判定に、保存した記録を使わず、許可の結果だけで判断する | 保存する値が増えない | アプリを開き直すと、まだ求めていない状態と見分けられない（どちらも `shouldShowRequestPermissionRationale` が false） |

## 結果

- 権限が外れたときに、どれを許可し直せばよいかが画面で分かる
- 通知の権限が無いことに、アプリを開いたときに気づける。ダイアログが出なくなっても、通知設定から許可できる
- この変更より前に 2 回拒否していた場合は、求めた記録が無いので、最初は「通知を許可する」が出る。押してもダイアログは出ず、その時点で「通知の設定を開く」に替わる
- 最初のダイアログを、拒否せずに外側を押して閉じた場合も、求めた記録が残るので「通知の設定を開く」が出ることがある。通知設定からでも許可できるので、そのままにする
