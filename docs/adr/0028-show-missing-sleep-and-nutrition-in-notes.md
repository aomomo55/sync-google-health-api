# 0028: 日次ノートで、睡眠と食事のデータが無いことを明示する

- ステータス: 採用
- 日付: 2026-10-24

## 背景

日次ノート（`server/src/notes/daily.ts`）は、値のある項目だけを本文のサマリーに出していた。

- 睡眠が無い日は睡眠の行ごと出なかった。まだ届いていないのか、記録が無いのかを区別できない。通知（[0022](0022-notify-missing-sleep.md)）を見逃したときに最後に気づける場所がノートなのに、何も書かれなかった
- 食事を記録していない日が、「食事: 0 kcal（P 0g / F 0g / C 0g）」と出る日と、行ごと出ない日があった。frontmatter の `摂取カロリー` なども 0 になり、「0 kcal 食べた」と「記録なし」を区別できず、Dataview・Bases のグラフや月次の平均にも 0 として入っていた

0 になる経路をコードで追うと、サーバーの変換やノートの生成は受け取った値をそのまま出しているだけで、0 を作ってはいない。Android の集計（`DayAggregator`）も、Health Connect の集計結果が無ければ `null` のまま送らない。0 が届くのは、Health Connect の栄養の集計（`NutritionRecord.ENERGY_TOTAL` など）が 0 を返した日で、その日に値が 0（または未入力）の栄養の記録がある場合と考えられる。行ごと出ない日は、その日に栄養の記録が 1 件も無いか、栄養の権限が無い日である。

## 決定

- 食事は、栄養の値（摂取カロリー・P・F・C）がどれも無いか、すべて 0 の日を「記録なし」とする（`hasNutritionRecord`、`domain/daily.ts`）
  - 本文には「- 食事: 記録なし」と必ず出す（行を消さない）
  - frontmatter の `摂取カロリー`・`たんぱく質g`・`脂質g`・`炭水化物g` は空にする（記録が 1 件も無い日と同じ）
  - 月次の集計（`摂取記録日数`・平均）にも含めない
  - 値が 1 つでも 0 より大きければ、0 の項目もそのまま出す（実際に 0 の項目がある記録を消さないため）
- 睡眠が無い日は、本文に必ず睡眠の行を出す
  - 翌日以降のデータがまだ無い日（最新の日）は「- 睡眠: まだ届いていません（ウェアラブルのアプリで同期すると、次の送信で反映されます）」
  - 翌日以降のデータが届いている日は「- 睡眠: 記録なし」
  - 区別には、ノートの前後のリンクに使っている「翌日」の有無（`HealthStore.findAdjacentDate` で求めた値）を使う。新しい日のデータが届くと前日のノートも作り直す（`affectedNotes`）ので、日付が変わってその日のデータが届いた時点で「記録なし」に替わる
  - frontmatter の睡眠の項目は、これまでどおり空のまま
- 日によって行を出したり出さなかったりしない。データが無いときの言葉は「記録なし」にそろえる
- Android 側は変えない。0 の扱いはノートの表し方の問題で、送られた値（0 を含む）は保存しておき、表し方をサーバーで決める

## 検討した選択肢

| 選択肢 | 長所 | 短所 |
|---|---|---|
| サーバーのノート生成で、値がすべて 0 の食事を「記録なし」として扱う（採用） | 保存済みのデータを直さずに、作り直したノートから正しくなる。Takeout から取り込んだ日にも効く | 本当に 0 kcal の日（絶食の日など）も「記録なし」になる |
| Android で、値がすべて 0 の栄養を送らない | 0 を保存しない | 送らない項目はサーバーの既存の値が残る（`POST /api/ingest` の約束）ので、既に保存した 0 は消えない。サーバーと Android に同じ規則を置くことになる |
| Android で栄養の記録を 1 件ずつ読み、値の入った記録だけを合計する | 「未入力」と「0」を区別できる | 読む量と処理が増える。値が 0 と書かれた記録は結局 0 になる |
| 睡眠の「まだ届いていない」を、生成した時刻で判断する | 区別が正確 | ノートの生成が決定的でなくなる（server/AGENTS.md の前提を壊す） |
| 睡眠が無い日は常に「未反映」と書く | 単純 | 過去の日にも「未反映」と残り、届くのを待つべきか分からない |
| frontmatter に「睡眠の状態」などの項目を足す | Dataview・Bases でも区別できる | 今の使い方（グラフと表）では要らない |

## 結果

- 睡眠の通知を見逃しても、ノートの最新の日で「まだ届いていません」に気づける
- 食事の表し方が「値」か「記録なし」の 2 通りになり、0 kcal と出る日が無くなる
- frontmatter の `摂取カロリー` などが 0 だった日は空になる。Bases の表ではその日のセルが空になり、ダッシュボードの「摂取と消費」のグラフでは 0 の棒が出なくなる。月次の `平均摂取カロリー` は記録のある日だけの平均になり、`摂取記録日数` は 0 の日を数えなくなる
- 既存のノートは、その日のノートを作り直したときに変わる。自動送信で作り直すのは直近の日だけなので、過去のノートを直すには `sync:notes` で期間を指定して同期し直す
- 本当に 0 kcal だった日も「記録なし」になる。実際にはほぼ無いので許容する
- 最新の日でも、データの途絶えた後の最後の日は「まだ届いていません」のまま残る
