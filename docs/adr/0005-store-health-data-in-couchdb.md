# 0005: 健康データを既存 CouchDB の別データベースに保存する

- ステータス: 採用
- 日付: 2026-10-03

## 背景

Android アプリから送られてくる日次データと、Takeout から取り込む過去データを保存する場所が必要になった。
当初は Google の OAuth トークンを保存するために Upstash Redis を使う予定だったが、Google の API を使わないことになり（[0001](0001-health-connect-as-data-source.md)）、その用途はなくなった。

## 決定

Obsidian の同期に使っている fly.io の CouchDB に、別のデータベース `health` を作って保存する。

- 1 日 1 ドキュメント（`_id: "day:YYYY-MM-DD"`）。睡眠は起床した日に属させる
- 項目は活動・心拍・体重・睡眠のセクションに分け、Google Fit の日別 CSV の列と単位（m、kcal、kg、bpm）に揃える
- 同じ日のデータを再送したときは、セクションごとに、送られてきた項目だけを上書きする

## 検討した選択肢

| 選択肢 | 長所 | 短所 |
|---|---|---|
| Upstash Redis | サーバーレスと相性がよい | サービスが 1 つ増える。範囲での取得に向かない |
| fly.io のボリュームに SQLite | 外部サービス不要 | ボリュームのバックアップが別途必要。複数台構成にできない |
| **既存 CouchDB の別データベース** | 新しいサービスが要らない。日付キーの範囲取得が `_all_docs` でできる。健康データが利用者の管理下から出ない | Vault と同じ CouchDB なので、権限を分けないと誤操作の影響が Vault に及ぶ |

## 結果

- サーバー用の CouchDB ユーザーは、可能なら `health` と LiveSync 用のデータベースだけに権限を絞る
- 保存処理は `HealthStore` インターフェースで抽象化し、テストではメモリ上の実装を使う
